# 从头实现规格书（给 LLM 的 Prompt 模板，2026-08-16）

> 用途：把 infcanvas 的设计思路概括成一份自洽的 prompt，让一个 LLM（无本项目上下文）从头
> 实现一个符合同样理念的"鼠鼠殖民地模拟"。原则是灵魂——实现若违反原则即为失败，无论功能多全。
> 使用：整份拷给代码 agent 作为任务说明；建议先让模型复述原则再开工（检验理解）。

---

## 任务

从零实现一个**鼠鼠殖民地模拟**游戏（轻量《边缘世界》/《矮人要塞》风）：一群鼠鼠小人，
0 操作也自主生存（采集→吃饭→睡觉→建造→社交→繁衍→遭遇敌袭与灾难），玩家/神谕只做慢决策
引导。TypeScript 单仓，浏览器 + Node 双端复用同一份**零 DOM 权威模拟**。

## 绝对设计原则（违反即失败，权重高于一切功能）

1. **一切皆抽卡**。每个小人的一切决策（吃/睡/工作/休闲/社交/发呆/违抗安排）都由**卡池抽卡**
   决定。决策引擎 = 给小人抽一张卡并执行其动作；卡权重受需求（饿/困/心情/理智）、欲望、
   熟练度、神谕目标、外部 mod 调制。**禁止 if-else 行为树、任务对列、强制指令式 AI**。
   卡 = `{ id, label, series(系列), weight, condition(谓词), action, 可选 workType/duration }`，
   按权重抽选；熟练度 = 卡的演化（触发↑、久不用↓，权重 ×(0.5+mastery/100)），**卡 = 习惯的建模**。
2. **尽量基础，交给涌现**。系统只提供**种子**（物品/建筑/敌人/事件/卡/工作/命令），
   不设计机制链：无任务系统、无主动技能/计时 buff、无延迟轰炸撮合、无资源硬约束规则、
   无剧情脚本、无胜负评分。事件从局面触发（谓词 + 效果表），不是脚本线。**输就是好玩**：
   死亡/灾难是故事不是失败。
3. **数据驱动**。一切数值（需求衰减速率、构筑血量、配方产出、事件权重、敌人属性…）进
   数据表（defs/tuning），系统只读表，禁止硬编码魔法数值；数值可被 mod 覆盖（overrideTuning）。
4. **一切皆插件**。内核 = 纯演算框架（最小：决策引擎 behavior + 社交/派系契约层），
   玩法（采集/狩猎/耕种/建造/医疗/交易/制衣/染色/监狱/科技/事件/敌袭/人口/家族…）全部是
   **玩法包**：`ModPack = { id, requires: string[], apply(m: ModRegistry) }`。
   - 注册面（公开 API）：registerSystemDef / registerCommand / registerItem / registerBuilding /
     registerRecipe / registerEnemy / registerEvent / registerStrategyCard / registerCard /
     registerWork / registerTech / registerHook / registerPredicate / overrideTuning / disableSystem。
   - 依赖显式声明 + 拓扑排序挂载（requires 拉齐顺序，清单乱序也正确）；**系统可单独装卸、
     单独测试**（系统只依赖 SimContext 接口，不碰 Sim 本体）；卸载不破坏核心。
   - **DLC = 独立玩法包**（requires: []），互相不依赖、不做互斥世界观。
   - 数据化部署：玩法内容可声明为纯 JSON 包（`mods/*.mod.json`：manifest + defs 数据表 +
     可选 scripts 函数式扩展），**放文件即自动部署**（目录扫描 + 挂载）。
5. **神谕只引导，不碰选择链**。神谕（玩家或 LLM 慢决策层）= 设目标/降旨：
   - **策略卡 = 神谕目标**：降旨 → 对应工作系列权重 ×N（如"伐木令"期间伐木卡权重×3），
     可选蓝图副作用（垦田令→农田蓝图入队）；**不插小人卡槽、不直接指挥单个小人**。
   - **科技 = 独立抽卡池**：顺序解锁（TECH_ORDER），建筑 tech 门控建造，科技卡带碎片机制。
   - LLM 可选作事件导演（叙事 feed）；**默认由随机抽卡完全替代，零 API 也能完整运行**。
6. **模拟真实性**。需求系统（食欲/睡眠/心情/理智）以速率衰减、以行动恢复；社交（协作/口角/
   关系数值）+ **传闻层**（"听说某营地有敌意历史 → 态度敌意"优先于数值关系——故事活在传闻里，
   参考矮人要塞）；地形真实（无限双图层 chunk、可开凿地形、水域、高差攀爬受 climb 限制）；
   敌袭/野兽/灾难按叙事压力生成；**捕猎/尸体/流血/伤口**是涌现素材不是特效。
7. **契约纪律**。跨包共享的字符串键（item.meta.xxx、pawn.extra.xxx）必须用**常量登记表**
   + 统一校验（写方/读方/客户端/服务端一律引用常量，拼错 = 编译期错误）；单包自洽键
   （写读同包）不入表但要有命名纪律。**色值 = 表现层数据**：逻辑层不持色值。
8. **文档即蓝本**。docs/ 是设计蓝本，**只能追加不能删改历史行**；每次代码变更同步文档
   （PROGRESS 进度表 / PLAYING 玩家可见 / DESIGN+DATA_DRIVEN 架构数据格式）。代码注释纪律：
   说明"做什么 + 为什么"（背景/动机/踩过的坑），禁止无注释魔法数字。

## 技术规格

- **src/sim = 权威核心**：零 DOM、零 Node API，可同时跑在 vitest / CLI / 浏览器 worker / 服务端。
- **双端复用**：浏览器渲染层只**读快照**；服务端 = WSS 权威 sim + 快照 diff 增量同步
  （~500ms 增量轮询 + ~5s 全量对账 + 新连接先收全量）；CLI（tsx）纯逻辑游玩（state/pawns/
  sel/move/build/job/oracle 命令）。远程协议 = 稀疏快照 + 命令 + 事件流。
- **寻路**：A*（二叉堆）+ 篝火航点中转（锚点对段缓存）+ 迭代上限双档（无火/有火）。
- **地图**：无限（双图层：地形/构筑，chunk 化、负坐标、脏区矩形增量渲染）。
- **存档**：纯 JSON；含 pawn.extra / building.extra / mod 自定义字段（扩展点，原样还原）。
- **渲染**：正交俯视、拖拽平移/缩放；建筑地基覆盖空气净化箱式渲染；小人 = 头像 + 需求图标
  + 状态徽记（征召金圈、穿戴标识）。

## 交付标准

- `npm test`（vitest）全绿：含每系统独立最小 ctx 单测、玩法包装配/卸载测试、依赖图/远程
  加载测试、契约校验测试；`npx tsc --noEmit` 干净。
- **一个可玩的完整循环**：开局 4 鼠鼠出生 → 自主采集/进食/睡觉/建造篝火与棚屋循环 →
  敌袭（战或逃）→ 玩家降旨引导工作 → 神谕策略卡/科技抽卡可见 → 存档读档。
- **插件化可证**：至少 3 个玩法包（如 needs 需求包、gather 采集包、social 社交包）+ 1 个
  独立 DLC 包（requires: []，可装卸、不影响默认装配）。
- **文档**：DESIGN.md（架构）/ DATA_DRIVEN.md（数据表格式与注册面 API）/ PLAYING.md
  （玩家操作）各一份。

## 工作方式（给实现 agent）

- 分阶段提交：① sim 骨架 + 卡池决策引擎（能跑：0 操作自主生存循环）→ ② 玩法包拆解 →
  ③ 数据化部署（.mod.json）→ ④ 渲染/联机/存档。
- 每个系统独立可测；**改内核前先问"能不能做成玩法包"**；内核不塞玩法。
- 开工前用两三句话复述上述原则（尤其"一切皆抽卡"与"神谕只引导"），确认理解后再写代码。
