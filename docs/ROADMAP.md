## R1 联机还账（P0，阶段④已知限制清零）

### R1-1 断线重连 + 心跳看门狗
- **目标**：网络抖动/服务重启后页面自愈，不手动刷新。
- **任务**：
  1. 客户端 `remote.ts`：onclose 后指数退避重连（0.5s→8s 封顶），重连成功即重新走 welcome 对齐；
  2. 服务端 `game-server.ts`：每 10s 一帧 `{t:'ping'}`；客户端 15s 未收到任何消息判定假死主动断开重连；
  3. HUD 断连期间顶部显示「⚠ 与服务器失去连接，重连中…」。
- **验收**：手动 kill 再重启 server，页面 ≤10s 内自动恢复且世界状态对齐（对齐判定=收到新 full 且 time 前进）；vitest 用 fake timer 模拟断连序列。
- **涉及面**：`src/client/remote.ts`、`src/server/game-server.ts`、`shared/protocol.ts`（ping）、`hud.ts`。

### R1-2 可选 Token 鉴权
- **目标**：公网部署不被陌生人指挥。
- **任务**：`SERVER_TOKEN` 环境变量设置后，ws 握手校验 `?token=`（不匹配 close(1008)）；未设=完全开放（本地开发默认）。
- **验收**：设 token 后无 token 连接被拒 + 有 token 正常；不设时行为不变。纯函数抽离可单测。
- **涉及面**：`game-server.ts`（握手回调）、新增 `server/auth.ts`。

### R1-3 远程渲染插值
- **目标**：消除 500ms 快照的传送感。
- **任务**：RemoteSim 保留实体上一帧位置，渲染按 `pos = lerp(prev, next, k)` 平滑（k 随 delta 间隔归一）；full 到达直接吸附。
- **验收**：肉眼平滑；快照对拍测试保证逻辑状态不受插值污染（插值只存在于渲染层副本）。
- **涉及面**：`remote.ts`（prev/next 双缓冲）、`render.ts`。

### R1-4 框选批量指挥
- **目标**：一群鼠一起走。
- **任务**：左键拖拽=画选框（拖拽平移改由中键/右键拖或空格+拖），框内鼠全部入选；move 命令本就支持 eids 数组。
- **验收**：框选 3 鼠右键移动 → 3 只同时进入 holdUntil 窗口并到达目标附近。
- **涉及面**：`main.ts`/`render.ts`（选择层）、协议无需变。

### R1-5 服务器侧存档
- **目标**：联机局也能存续（现在只有浏览器 localStorage）。
- **任务**：管理命令 `save`/`load`（仅限 source='system' 或加 admin token）：写 `saves/<时间戳>.json`；启动参数 `--load <file>`。
- **验收**：存→杀服→载→继续跑，确定性续跑对拍在服务器路径同样成立。
- **涉及面**：`server/index.ts`、复用 `snapshotOf/loadSim`。

## R2 阶段③补全（P0，原路线图被跳过）

### R2-1 科技 = 独立抽卡池（碎片制）
- **目标**：解锁进度本身也是抽卡——攒碎片而非直发整卡（蓝图原则⑤保留条款）。
- **任务**：
  1. 数据表：`tuning.techs` 或 defs 表 `TechDef { id, name, fragments, order }`，TECH_ORDER 数组定顺序解锁；
  2. tech-pool 包：系统按间隔发**科技碎片**（权重=TECH_ORDER 线性递减，靠前的先攒齐），攒满自动解锁并发事件；
  3. 门控消费：BuildingDef 增可选 `tech` 字段，build 包落子前查门控；
  4. 存档随档（techFragments/unlocked 入 SaveData）；
  5. HUD 科技面板显示 🔩 x/N 进度。
- **验收**：固定 seed 下解锁顺序符合 TECH_ORDER 概率预期（统计测试）；卸载 tech-pool 包=永无科技但核心照跑；存读档碎片数一致。
- **涉及面**：新包 `mods/packs/tech-pool.ts`、`sim/sim-save.ts`、`building.ts`、`hud.ts`。

### R2-2 .mod.json 数据化部署
- **目标**：放文件即装 mod——内容种子（物品/建筑/敌人/事件/卡）声明为纯 JSON，不改代码。
- **任务**：
  1. 格式：`{ manifest: { id, requires, title }, defs: { buildings:[], enemies:[], items:[], cards:[] } }`（cards 的 condition/action 无法 JSON 化→v1 仅支持**无谓词卡**或引用 registerPredicate 已登记名）；
  2. 加载器 `server/mod-loader.ts`：扫描目录 → topoSort（复用 pack.ts）→ 逐 def 调注册面 → validateContracts；
  3. CLI：`npm run mods -- [目录] [--dry]` 报告装载清单与错误；
  4. 示例包 1 个（如 `mods/sample-berry.mod.json` 新浆果品种+新敌人）。
- **验收**：目录放入 .mod.json 重启自动生效；缺依赖/重复 id 报错且不半挂载；坏 JSON 给出文件名级错误定位。
- **涉及面**：新增 `server/mod-loader.ts`、`shared/mod-schema.ts`、示例 `mods/`。

### R2-3 DLC 式独立包示范
- **任务**：把 R2-2 示例同时做成 TS 包版本（requires:[]），证明"同一内容、两种部署形态"。
- **验收**：assembly 测试挂载/卸载不影响默认装配。

## R3 玩法种子第一批（P1，原则②：只给种子，涌现自己长故事）

> 通用约束：每个包独立 ModPack、数值全进 tuning、最小 ctx 可单测、卸载不破坏核心。
> 卡一律进现有卡池参与抽签，**禁止任何直控**。

### R3-1 欲望层（needs 包扩展）
- **内容**：欲望=缓慢积累的第二类权重输入（如"闲逛欲"久留不动上涨→推 wander/social 权重）。数据表驱动，2~3 条起步。
- **验收**：统计测试证明欲望调制方向正确；随档。

### R3-2 农耕包（farming）
- **种子**：耕地建筑(1×1)、播种/收获卡、作物生长=地块冷却的变体；收获入 food。
- **涌现点**：没人播种就饿肚子——生存压力自己逼出农业。
- **验收**：完整耕收闭环统计测试；卸载包后农田留存但不产出。

### R3-3 狩猎包（hunting）
- **种子**：被动动物（兔/鹿：游荡+受击逃跑）、狩猎卡（追击+拾尸取肉）、肉=高饱食食材。
- **涌现点**：猎物会逃→追逐战；猫也会咬兔子→生态竞争。
- **验收**：捕猎链路测试；动物表数据化。

### R3-4 篝火烹饪（cooking）
- **种子**：生食低收益/熟食高收益，"烹烤"卡需在火旁；火的价值再+1。
- **验收**：食用收支平衡测试（熟食净收益>生食）。

### R3-5 医疗简版（medicine）
- **种子**：重伤状态（hp<30% 移动减速）、"照料"卡（在旁缓慢回血）、病榻建筑占位预留。
- **验收**：照料加速回复测试；无医疗时自然恢复慢但不死循环。

## R4 敌袭与事件扩充（P1）

- **敌人表扩容**：狼群（3~4 只协同追最近）、石壳兽（高血低速、拆建筑）——全部 tuning.enemies 数据行 + raid 包分支按 kind 最小化。
- **局面事件种子包（events）**：丰收（地图浆果瞬时+50%）、寒潮（食物衰减×1.5 一段时间）、流浪者（加入一只鼠）。形态=predicate+效果表（registry.registerEvent 已有登记面），**无脚本线**。
- **验收**：每事件一条"局面触发"测试；事件频率进 tuning。
