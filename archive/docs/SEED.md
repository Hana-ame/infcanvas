# SEED —— 一句话种子（2026-10-07）

> 用法：这一句话是整个项目的生成入口。`REIMPLEMENT_PROMPT.md` 是"规格书"，
> 本文件是"种子"——一句话里同时压着设计灵魂与要做的内容。
> 任何实现、任何玩法包，都必须能回答"这句话里的哪个词要求你做这件事"。

---

## 种子（一句话）

> **一群各有需求、技能、特质与人际关系的鼠，在无限生成的野外里，靠一张一张抽出的
> 行为卡自主采集、耕种、烹饪、建造、狩猎、防御、结盟与贸易——饥荒、寒冬、瘟疫、
> 突袭与背叛都不是脚本，而是同一套抽卡池在不同局面下抽出的不同故事。**

| 词 | 含义 | 落地形态 |

| **特质** | 5 种特质按系列乘权重 | `tuning.traits`（已有） |

| **一张一张抽出的行为卡** | 一切皆抽卡（红线，不可违反） | `sim/cards.ts` + `behavior` 系统（已有） |

## 生成纪律（从这句话派生，不可违反）

1. **一切皆抽卡**——新玩法一律注册卡 + 权重钩子；**禁止**行为树、任务队列、
   强制指令式 AI、"××令"。玩家干预面只有 `move` / `save` / `load`。
2. **先问"能不能做成玩法包"**——改内核前必须先证明它不能做成包。
   内核已扩展的例外只有两处：敌人 `drops`/`passive` 字段（掉落是数据事实）、
   死亡掉落写入 stockpile（世界事实，随档）。
3. **数值全进 tuning**——新增包一律 `tuning.<包名>` 区块；registerCard 时拿不到 ctx，
   卡权重写死在包里，可 A/B 的玩法量（半径/时长/收益）留 tuning。
4. **卸载不破坏核心**——每个包声明 `requires`；卸载后残留数据（建筑/库存）不报错、不产出。
5. **确定性优先**——`fingerprint.ts` 指纹变更必须换血 `golden.test.ts` 基线并注明理由；
   内核改动要设计成"无包挂载 = 零行为变化"，让基线尽量不动。
6. **磁铁范式**——"需要先靠近才能做"的行为一律拆两个半径：
   `condition` 用磁铁半径（看得见、值得走过去），`action` 里用工作半径（伸手可及），
   中间用 `setPath` + `return` 等 `moveStep`。**已踩坑 5 次**（chat/sow/harvest/sleep/cook）。
7. **测试纪律**——新包必须自带方向性单测 + 装配/卸载测试 + card-liveness（卡不得抽中占比 <0.2%）。
